# 佳木的待办助手 · 使用说明

一个装在手机桌面上的「周度任务 + 习惯 + 愿景」工具。数据只存在你自己手机里，不上传任何服务器。

**在线地址**：https://moonlit-firefly.github.io/todo/
**当前版本**：v22

---

## 一、四类东西，分开记录

| | **任务** | **习惯** | **愿景** | **事件** |
|---|---|---|---|---|
| 是什么 | 做完就结束的事 | 需要反复做的事 | 长期方向，没有期限 | 只记录「做了几次」的事 |
| 在哪 | 周度页 | 习惯页 · 日度 / 周期 | 习惯页 · 愿景 | 事件页 |
| 例子 | 「周五交方案」 | 「每天喝水」 | 「跑一次半马」 | 「游泳」「请客吃饭」 |
| 怎么记 | 勾选完成 | 每天打卡 | 想到了就做，不催 | 点 ＋ 加一次 |
| 属性 | 星级 + 截止日期 | 星级 + 刷新周期 | 星级（可选截止日期） | 星级 |

**为什么任务不再分「重要 / 紧急」**

因为这两个维度已经被别的东西表达了：

- **重要性** → 星级。5 星就是真正重要、不能拖的。
- **紧迫性** → 截止日期。快到期的自然排前面。

再挂两个开关，等于同一件事说两遍，而且很容易出现「我标了重要，但它其实不急」这种自相矛盾的记录。现在排序只剩一条规则：**星级高的先做，同星级里截止时间近的先做**。

**为什么把「长期」改名叫「愿景」**

原来的「长期」其实不是待办——它没有完成的那一天，也不该被每天刷新催。叫「愿景」更准确：它是一个方向，不是一个任务。数据完全没变，只是名字和位置变了。

## 二、周度页（主页）

### 1. 三个子页

顶部可以在 **规划 / 未完成 / 已完成** 之间切换，**默认是「未完成」**。

| 子页 | 看什么 |
|---|---|
| **规划** | 这一周的全部安排（含已完成的），按今日 / 本周 / 待安排分组，用来排期 |
| **未完成** | 只看还没勾掉的：今日 / 本周 / 之后 / 无期限 |
| **已完成** | 这一周实际完成了什么，每条带完成时间 |

### 2. 内容怎么分组

**当前这一周**按截止时间自动分成四块：

| 区块 | 放什么 |
|---|---|
| **今日待办** | 截止时间在 **24 小时内**的待办 / 习惯 / 愿景（**已逾期的也在这里**） |
| **周度待办** | 截止时间在 **本周末（周日结束）前**、但还没进 24 小时窗口的 |
| **之后** | 截止时间在本周以后的 |
| **无期限** | 没有设截止日期的任务 / 愿景，提醒你尽快排期 |

**排序规则**：星级高的在前 → 同星级按截止时间近的在前 → 再按创建时间。

**看历史周 / 未来周**：用日期两边的 **‹ ›** 翻周。翻到别的周时，不再用「今天」当基准，而是直接看那一周自己的日期范围，配合「已完成」子页就能回看当时完成了什么。

### 3. 右侧日历

点右上角的 **📅**，从右侧滑出日历：

- 每个月一屏，**颜色越深 = 那天完成的条目越多**（任务 + 习惯都算）。
- 点任意一天 → 直接跳到那一天所在的周，日历自动收起。
- 日历下方有本月概览：**规划 / 未完成 / 已完成** 三个数字，以及**每条习惯、愿景在本月完成了多少次**。
- 点「查看月度详情 ›」进入完整的月度页。

### 4. 月度页

点右上角的 **月**，或在日历里点「查看月度详情」：

- 三个数字：**规划**（本月有截止日期的条目）、**未完成**（其中还没勾掉的）、**已完成**（本月实际完成次数）。
- 下面列出每条习惯 / 愿景在本月的完成次数。
- 用右上角的 **‹ ›** 翻月份。

> 「已完成」可能大于「规划」：因为一条每天打卡的习惯，一个月会完成很多次，而它在「规划」里只算 1 条。

### 5. 加号

右上角的 **＋** 用来新建。新建时会让你选类型：

- **不重复（任务）** → 出现在周度页
- **每天 / 每 N 天刷新的习惯** → 出现在习惯页
- **愿景（长期方向）** → 出现在习惯页的「愿景」子页

新建任务时建议顺手设截止日期——没有截止日期会掉进「无期限」，不会自动排进本周。

## 三、习惯与愿景

顶部三个子页：

| 子页 | 行为 | 适合 |
|---|---|---|
| **日度** | 每天凌晨 4 点刷新为未完成 | 每天喝水、每天读书 |
| **周期** | 你设的天数到了才刷新 | 每 3 天浇花、每 7 天复盘 |
| **愿景** | **永不刷新** | 跑一次半马、学会一门乐器 |

**刷新倒计时**：

```
每天刷新 · 还剩 8 小时
每 3 天刷新 · 还剩 2 天 6 小时
愿景                          ← 不刷新，所以没有倒计时
```

**星级**：可以给每条打 0～5 星，星级越高排得越靠前。未完成的排在已完成的前面。

**愿景也能排期**：如果某条愿景到了该动手的时候，在它的截止日期里填一个时间，它就会自动出现在周度页的今日 / 周度待办里；把日期清掉就回到愿景页。

## 四、事件

用来记录「做了几次、每次怎么样」的事：游泳、跑步、请客吃饭、看医生……

| 操作 | 结果 |
|---|---|
| **点事件那一行** | 进详情页，看它的每一条记录 |
| 点右边蓝色 **＋** | 直接记一次 |
| 详情页点**某一条记录** | 改这条的时间和内容，也可以删掉 |
| 点**事项名字**／长按 | 改名、改星级、删除整个事件 |

每次记录包含：**什么时候**（默认当前时间，可改）+ **写点什么**（可留空，写心得和下次的改进）。

**默认自带一个「游泳」事件**，可以直接用，也可以改名或删掉。

## 五、数据统计

顶部切换 **近 7 天 / 30 天 / 90 天**，下面三个子页：**任务 / 习惯 / 事件**。

#### 📋 任务

| 卡片 | 看什么 |
|---|---|
| **概览** | 未完成任务、逾期数、逾期率、今日完成、今日新增、完成/新增比 |
| **时间分布** | 未完成任务按「今日 / 本周 / 之后 / 无期限」的构成 |

> 「无期限」占比高，通常意味着你在攒事而不是在排期。

#### 🔄 习惯

| 卡片 | 看什么 |
|---|---|
| **今日打卡** | 今天完成了几条习惯，进度条形式 |
| **打卡热力图** | 每天一个方块，颜色越深表示当天完成的习惯越多 |
| **习惯稳定度** | 每条习惯的实际/应完成次数、完成率、当前连续天数、历史最长连击 |

完成率最低的排在最上面，优先看它们。

#### 🏊 事件

| 卡片 | 看什么 |
|---|---|
| **概览** | 窗口内次数、累计次数、平均每天/每周、有记录的天数、活跃事件数 |
| **每个事件** | 每个事件一行：窗口内次数 / 累计次数 / 写了多少条内容 / 多久没记 |
| **写过的内容** | 把各事件里写过的内容按时间倒序汇总，最近 6 条 |

**窗口内次数**只算你选的时间段；**累计次数**从事件建立到现在，不受窗口和日志裁剪影响。

## ⭐ 星级：决定谁排在前面

**任务、习惯、愿景、事件**都带星级，**星级越高越靠前**。

### 怎么设置

打开编辑面板，找到「重要程度」那一行：

| 操作 | 结果 |
|---|---|
| 点星星的**左半颗** | 半星（0.5） |
| 点星星的**右半颗** | 整星（1） |
| **再点一次当前那一格** | 清零（恢复成没打星） |

范围 0 ～ 5 星。

### 排序规则

- **任务（周度页）**：星级高的靠前 → 同星级按截止时间近的 → 再按创建时间
- **习惯**：未完成在前 → 星级高的靠前 → 同星级按创建时间
- **事件**：星级高的靠前 → 同星级按创建时间

### 建议怎么用

不用每件都打星，否则等于没打。可以只分三档：

- **5 星** —— 真正重要、不能断的
- **3 星** —— 常规要做，但可以缓一天
- **不打星** —— 顺手做的小事，排后面不碍事

星级是给你自己排序用的，**不影响统计口径**，只有列表顺序会变。

## 六、刷新规则：凌晨 4 点

**「一天」的分界线是凌晨 4 点，不是 0 点。**

- 晚上 11 点打卡，凌晨 2 点再打开，**仍然是已完成** —— 熬夜党不会被莫名重置
- 到了第二天凌晨 4 点，才刷新为未完成
- **一周从周一凌晨 4 点开始**，「本周末前」指到周日结束

**刷新是怎么发生的**：网页无法在后台常驻，所以用的是「惰性结算」——在你**打开应用、从后台切回、或应用开着时每分钟**检查一次。效果和 4 点自动刷新一致，只是要等你下次打开才看得到。

### 截止时间不走 4 点分界

截止日期走**精确时刻**：设「截止 18:30」，到 18:30 整就显示「已逾期」。界面的倒计时、统计里的逾期数、周度分组，用的是同一个时刻。

## 七、数据：只在你手机里

### 存在哪

手机浏览器的本地存储（localStorage），键名 `dsh.todo.v2`。**完全不上传**——代码里没有任何网络请求，飞行模式下也能正常使用。

### 三个保护机制

| 机制 | 说明 |
|---|---|
| **每日自动快照** | 每天第一次打开自动留一份，保留最近 3 份 |
| **删除可撤销** | 删掉后 6 秒内底部会弹「撤销」 |
| **损坏保护** | 数据读取异常时，原始内容会被保留并可下载，不会被覆盖 |

### 和旧版本的数据兼容

这次大改**没有改存储结构**，旧数据会原样读出来：

- 旧任务的 **重要 / 紧急** 字段还留在数据里，但界面不再使用它——不会丢，也不会再影响排序。
- 旧的「长期」就是现在的「愿景」，只是改了名字，数据还是同一个 `someday`。
- 旧任务有截止日期的，自动进入周度 / 月度；没有截止日期的进入「无期限」，不会消失。
- 星级、完成状态、习惯的连续天数、历史记录、事件记录，全部保留。

**第一次打开新版本时，建议先导出一次备份**，然后再慢慢适应新界面。

### 手动备份（重要）

`⋯` → **导出备份** → 得到一个 JSON 文件，存到网盘或发给自己。

**建议每周导一次。** 清理浏览器缓存、卸载浏览器、换新手机，本地数据都会消失。

**误删了怎么办**：`⋯` → **从自动快照恢复** → 选一份恢复。恢复前当前数据也会自动存一份。

### 换手机 / 多设备

导出 JSON → 在新设备上打开同一个网址 → `⋯` → **导入备份**。

> 注意：**不支持自动同步**。手机和电脑各存各的，互不影响。

## 八、装到手机上

1. 手机浏览器打开 https://moonlit-firefly.github.io/todo/
2. 浏览器菜单（⋮）→ **添加到主屏幕**
3. 从桌面图标打开，**没有地址栏**，跟正常 App 一样

**验证是否正常**：

- 打开后**等 3~5 秒**再关，让离线缓存写完
- 开**飞行模式** → 打开应用 → 能正常用 = 离线缓存生效
- 新建几条 → 完全退出 → 重开 → 数据还在 = 本地存储正常

## 九、常见问题

**Q：我的旧数据会乱吗？**
A：不会。存储结构没变，旧的待办、习惯、事件、星级、完成记录都会原样显示。旧任务会按截止日期自动分到「今日 / 本周 / 之后 / 无期限」。第一次升级前建议先导一份备份。

**Q：为什么「重要 / 紧急」没了？**
A：它们和星级、截止日期重复了。现在星级表达重要性，截止日期表达紧迫性，排序只按这两样。

**Q：习惯为什么不出现在周度页？**
A：只有**设了截止日期**的习惯 / 愿景才会进入周度页（因为周度页是按截止日期分组的）。没设日期的习惯留在习惯页，按自己的周期刷新。

**Q：日历上的数字是什么？**
A：那天完成的条目数。任务算勾选完成，习惯算打卡，同一条同一天只算一次。

**Q：月度页的「已完成」为什么比「规划」大？**
A：习惯每天打卡，一个月会完成很多次；它在「规划」里只算 1 条。

**Q：为什么提醒时间不弹通知？**
A：这需要系统级权限（闹钟、状态栏通知），网页做不到。目前的替代方案是把截止日期记下来。

**Q：为什么统计页刚打开时数字很少？**
A：数据是**从现在开始记录**的。历史只能靠已有待办补出「创建」和「完成」两个时间点。用得越久，趋势越有意义。

**Q：改了名/换了图标怎么办？**
A：桌面图标的名字可能要过一阵才更新（安卓的已安装应用有独立缓存）。等不及就长按图标删掉，重新「添加到主屏幕」。**数据不会丢**，数据跟着网址走，跟图标无关。

**Q：习惯的连续天数怎么算的？**
A：今天还没打卡**不算断连**；断档超过一天才归零，但「历史最长」会一直保留。

**Q：清空数据后还能找回吗？**
A：能。清空前会自动存一份快照，用 `⋯` → 从自动快照恢复 可以找回。

## 十、更新应用

1. 打开 GitHub 仓库 https://github.com/moonlit-firefly/todo
2. **Add file** → **Upload files**
3. 把改动过的文件拖进去覆盖（通常是 `index.html` 和 `sw.js`）
4. **Commit changes**
5. 等约 10 分钟（GitHub 有 CDN 缓存）
6. 手机上打开应用 → 完全关掉 → 再打开

> `sw.js` 里的 `VERSION` 每版都会加一（现在是 `todo-v22`），这是让旧缓存失效的开关。**改代码时如果不改这个版本号，手机会一直看到旧版本。**
> 更新只换代码，**不影响你的数据**。

## 十一、技术说明

| 项 | 值 |
|---|---|
| 形态 | 单页 PWA，纯静态，无后端 |
| 依赖 | 无。全部是内联 HTML/CSS/JS，运行时零请求 |
| 离线 | Service Worker 缓存优先，秒开 |
| 数据 | localStorage，键名 `dsh.todo.v2` |
| 时间基准 | 凌晨 4 点（`DAY_OFFSET`）；周从周一凌晨 4 点开始 |
| 统计基础 | `db.log` 用于任务完成与习惯打卡；事件统计只看事件自己的记录 |

### 文件清单

```
index.html            应用主体（界面 + 逻辑，全内联）
sw.js                 Service Worker（离线缓存）
manifest.json         PWA 清单（应用名、图标、独立窗口）
icon-192.png          图标
icon-512.png          图标
apple-touch-icon.png  iOS 图标
README.md             本文档
```
